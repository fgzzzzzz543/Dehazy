# CNN 轻量化与受控实验

## 1. 冻结基线与部署目标

先查实际网络、checkpoint、数据协议、输入/输出大小、预/后处理和当前实现瓶颈，而不是从“再剪枝/再量化”开始。

- 记录参数量、真实前向图的层形状与 MAC，说明一次 MAC 如何计数。网络改宽或改尺寸后重新统计，不用不匹配分辨率的旧值。
- 将模型权重、峰值激活、skip/分支缓存、外存访问、并行尾块利用率分别记录；小模型不必然有高系统吞吐。
- 将主机各阶段计时、RTL 周期分类、实际综合资源/时序和板端计数分开。缺哪类证据就标未测，不能从 MAC 降幅直接填 FPGA FPS。
- 明确目标器件/时钟、输出质量预算、目标端到端负载，以及训练/综合时间预算。质量预算未知时可作探索和报告差值，但不能宣称达标。

本项目曾用“平均PSNR下降不超过0.2dB、SSIM下降不超过0.002”的特定协议；这些是该实验预先冻结的要求，不是所有模型的默认门槛。

## 2. 一次定义清楚一个候选因子

优先从已存在的实现和瓶颈选择方案，不同时改变网络、数据、监督和评测口径后单独归因。

| 方向 | 控制变量与观察项 | 不能直接声称 |
| --- | --- | --- |
| 通道宽度/结构收缩 | 同划分、同监督、同优化预算和样本暴露；真实图参数/MAC、画质、尾块利用率 | 参数量下降就会同比减少完整系统周期 |
| CNN 局部分辨率下降 | 保持最终输出与其匹配的全分辨率基线；冻结缩放算子、坐标和边界，明确哪些分支仍是全尺寸 | 拿不同输出分辨率的PSNR直接相减，或把降采样系统称为原算法逐位等价 |
| 量化与混合精度 | BN折叠、校准来源、per-channel/per-tensor、符号、截断/饱和/环绕、重定量边界 | 含FP32层间边界的实现就是端到端全INT8 |
| 轻量候选微调 | 冻结父权重，新输出路径；有限训练集、预算、BN策略、监督、选模标准 | 少量场景pilot等于完整重训或独立测试胜出 |
| 结构化剪枝/教师蒸馏等扩展 | 仅当本次任务需要且有明确方案时新建协议、比较条件和基线 | 因为用户说“蒸馏skill”就认为做过模型知识蒸馏 |

宽度或分辨率变化后的模型不是旧模型的数值等价实现；画质达标后，应把新模型冻结为其自身的实现参考。

## 3. 受控训练与候选选择

- 按内容/场景隔离训练、验证、测试，处理清晰图别名及重复雾化版本，不能只按文件名随机拆分。
- 比较同监督目标；物理额外损失是独立因素，不把不同监督的结果写成“只有网络架构不同”。
- 固定划分种子；改变训练种子时明确它影响初始化/样本顺序/增强，不偷偷重划数据。
- 同一比较内复用或核验样本/增强轨迹、训练暴露量、学习率与选checkpoint规则。输入签名不等于全张量逐位一致或跨平台确定性证明。
- 验证集选模型，按预定平局规则；结构筛选不反复使用测试集。试验过的测试集不得再次叫“全新盲测”。
- 单种子筛选后，若要论证稳定性，应按既定预算报告全部预定种子、均值、样本标准差和配对差值。图像数不是训练重复次数；不只汇报最佳种子。
- smoke/预检与正式初始化隔离；恢复训练先查已有进程、完成标记和协议哈希，不静默覆盖或自动多次续跑。

## 4. 低分辨率分支：避免改变没有打算改变的路径

本项目的有用模式是“全尺寸预/后处理，只缩小CNN分支”。实际依赖以当前模型定义为准：

- DCP、同帧大气光、原始透射率和RGB等若被声明保持全尺寸，就不能在优化时改成低尺寸重算或复用上一帧值。
- 明确下采样是逐级还是一次完成，插值模式、align_corners、antialias、像素中心与边界；上采样及融合顺序同样冻结。
- 使用与当前最终输出尺寸匹配的全尺寸FP32基线，分别计入下采样、CNN、上采样和重建成本；共享预处理成本不能漏算。
- 除总体PSNR/SSIM外，保留按预定义场景/浓度的结果和最差样本；边缘诊断不是自动的语义天空分割，也不能事后新增通过门槛。
- 软件通过只支持质量/算法筛选。真实DDR、完整尺寸RTL和整板运行仍需独立验证。

## 5. 量化必须守住增量与累计预算

当“降分辨率 → 量化 → 微调”串联时，同时报告：

```text
incremental_drop = 上一阶段同尺寸浮点参考指标 − 当前候选指标
cumulative_drop  = 原始匹配输出尺寸参考指标 − 当前候选指标
```

对PSNR/SSIM等越高越好的指标按这个方向写；若指标方向不同，明示定义。不能每一步都说“只掉一点”，却不检查累计损失。

- 校准只使用协议允许的数据；记录场景清单、数量、浓度覆盖、percentile和采样方式。不要用最终测试集调校准参数。
- 仅当图语义证明输入非负时选择UINT8，不凭激活样本恰好非负作证明。
- 新微调权重意味着新身份；重新校准/导出/数值验证，不复用旧量化因子或旧RTL通过结论。
- 保存溢出/饱和、层间误差和坏样本；校准流程完成与质量门槛通过是两种状态。
- 只有确实实施时才标“QAT”或“蒸馏”，普通校准/后量化/微调不改名冒充这些方法。

## 6. 用瓶颈实测引导硬件协同优化

先做不改变数值定义的优化，再在必要时单独开启数值格式分支：

1. 建互斥周期分类验证总周期守恒；AXI/FIFO/MAC/trace等可以重叠的事件不相加当总等待。
2. 核对量化/去量化、外存访问和写回是否主导；合并突发、局部复用、结果消费与装载解耦要有真实事务/握手/周期证据。
3. 需要双缓冲时明确loader/compute/drain所有权；不要因模块名有“pipeline”就宣称真实装载和计算已重叠。
4. BRAM推断看实际综合结果。此工程出现过多过程写同一bank导致仿真通过但未推断BRAM的情况；应整理单一写入口后复验，而不是只加属性。
5. 报告完整尺寸与约束下的时序、DSP/LUT/FF/BRAM及DDR实际条件。不要换器件、降时钟或只报局部OOC来隐去失败。
6. 选保留质量预算且有实证收益的候选；未测的整板FPS继续标未知，不为凑“最佳”而编数。
