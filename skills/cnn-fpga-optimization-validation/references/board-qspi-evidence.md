# 上板与 QSPI 证据核对

本skill提供流程，不默认授予硬件操作权限。只做分析/创建skill/整理文件时保持离线。需要连接、复位、下载、Flash写入或恢复时，以当次用户要求和已确认目标为边界；历史脚本、文档和旧授权不能替代它。

## 1. 先对齐当前身份

核对源码/权重与构建参数 → BIT/XSA → PS应用/FSBL → BIF/BOOT → 执行记录与原始样本。目录名“latest”和旧README不是身份凭证。保留阶段日期、输入负载、工具版本和原始哈希。

不同版本证据可以提供背景，不能跨镜像拼成新的通过报告；算法文件相同也不代表更改后硬件仍有相同吞吐、画质或稳定性。

## 2. 六个独立状态

| 状态 | 所需证据 | 不能替代 |
| --- | --- | --- |
| 实现完成 | 当前完整顶层的资源/时序/DRC/CDC、BIT/XSA | 板端运行 |
| JTAG应用运行 | 匹配下载命令、运行日志、输出/计数 | Flash固化或冷启动 |
| BOOT生成 | BIF分区及匹配FSBL/BIT/应用，bootgen返回码、产物哈希 | Flash已写入 |
| Flash读回通过 | 目标、备份、地址/大小、写入返回码、逐区间读回比较 | 独立完整断电冷启动或整片转储一致 |
| QSPI运行观察 | 匹配上下文、启动模式/CPU/应用状态、动态输入与输出/计数 | 有完整记录的冷启动/长稳 |
| 完整冷启动和长稳 | 独立记录断电—配置—上电全过程与明确持续时间、故障/输出观察 | 未执行的现场画质或功耗测量 |

## 3. 若本次明确要求固化

- 先确认设备身份、容量/布局、旧Flash可用备份及哈希、目标镜像及写入范围；不确定时停止在离线准备，不自动“试烧”。
- 检查当前PS配置与板卡QSPI引脚/DDR配置匹配，用当前XSA构建FSBL与应用；本案MIO1–6、库和器件参数不是通用默认值。
- 保留命令和工具日志，明确擦写区域，不默认整片擦除；结果不明时不重复编程来“碰碰运气”。
- 读回比对写入镜像全部字节并记录范围；工具 `-verify` 与独立整片dump分开描述。
- 新BOOT不能继承原镜像的板测结果。读回通过后，冷启动、动态输入、连续运行须按实际执行逐项验收。
- 原始失败/中断尝试保留；旧状态文件不改写成后来的成功。备份不公开上传，不因有备份就默认授权恢复。

## 4. 若本次仅要求运行核验

优先现有原始样本复算。用户明确要求新只读采样时，检查唯一目标、已运行状态和MMIO白名单；不能为读取计数而自动halt/reset/清零/写寄存器，条件不满足就停止硬件动作。

对同一快照的帧计数与时间戳做一致性检查，必要时重读关键计数确认未跨事件。记录读取时间和重试；调试总线只读也可能扰动，不能宣称绝对零影响。

本地BOOT文件与记录哈希一致只证明本地证据身份；不独立证明当前板上就是该镜像。启动模式寄存器、用户画面反馈、程序计数器增长也不单独证明完整冷启动已被记录。
