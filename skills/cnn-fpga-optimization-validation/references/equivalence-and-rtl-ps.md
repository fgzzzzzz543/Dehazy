# 冻结算法等价与 RTL/PS 集成

## 1. 定义参考链，而不是一个笼统“正确”

```text
原始浮点基线
  → 轻量化候选（任务质量预算，不要求对旧模型逐位等价）
  → 该候选的冻结数值/量化参考
  → 独立主机实现 / 单算子与单层RTL
  → 真正连接的完整RTL图
  → PS/PL端到端图像实现
```

固定网络拓扑、参数、布局、符号扩展、位宽、累加/溢出、bias/scale、重定量与舍入、饱和/环绕、插值边界、残差和裁剪顺序。整数/定点以冻结契约逐元素比较；浮点应在协议中选定逐位一致或合理绝对/相对/ULP容差，不把跨框架自动逐位相同当假设。

“同一权重文件”不足以证明数学实现相同；加载方式、张量顺序、算子参数和后处理也要匹配。更改会影响输出的定义时另立候选，不能通过放宽容差掩盖移植错误。

## 2. 从最早不一致处定位

- 校验输入与权重序列化、endianness、NCHW/NHWC/片上布局、五通道/残差等实际图接口。
- 逐层保存预期输入、累加器、重定量/去量化、插值/skip和最终结果；同时记录元素数量、差异数、首个差异和误差范围。
- CRC/哈希用于定位与身份；有原始字节时再做直接比较。独立生成期望，不能只比较同一错误实现产生的两个CRC。
- 用冻结自然输入、确定性随机、黑/白/极值、奇数尺寸、1×1及跨tile宽度覆盖边界；测试大小必须真正跨越目标硬件边界。
- 覆盖连续不同输入、同帧大气光/缓存失效、热重启、复位和状态重用；不能只重复一个静态黄金样本。

先定位哪层/哪条边界偏离，再改根因；不在最终输出打补丁，也不以视觉“差不多”替代数值验证。

## 3. 独立层夹具与完整图分开

若每一层的RTL输入来自软件expected文件，而不是上一层RTL输出，这只是**逐层独立夹具**。即使16层都通过，也不能称端到端完整RTL图通过。

完整图需确认：

- 上层输出真正进入下层，skip/concat/插值和量化边界完整连接。
- 输入到最终写回/完成事件覆盖完整真实图尺寸，不用小图周期外推实测完整图FPS。
- 背压、写回/trace排空、层切换、故障/复位和边界tile均按契约处理。
- 使用的RTL闭包、参数、权重、testbench与工具命令被记录；功能仿真、综合和物理实现状态分别保存。

## 4. AXI、缓存和并行化

对实际接口制定检查，不固定套用本案总线宽度：

- 地址/字节使能、对齐、尾拍、奇数word、burst上限、4KB边界以及 `RLAST`/写响应。
- 共享读通路事务所有权保持到最后一拍握手；阶段切换等待相关reader/writer/队列排空。
- 数据提交与trace/完成事件定义一致；不能在写响应成功前把输出当已提交。
- 有界FIFO的信用与背压、慢生产者排空、错误锁定、abort和复位恢复；不能自动宣称在途AXI错误后无损恢复。
- BRAM端口和buffer所有权明确。每周期事件可重叠，与总周期互斥分类分开计。
- DW/PW等局部融合若存在，保持已冻结量化、插值和算术边界；计算顺序改变影响浮点结果时按契约重新验收。

## 5. PS/PL 与视频集成

- 确认PS预处理、PL推理、PS重建、视频DMA以及CPU/PL端的地址映射、缓存一致性和数据布局；在实际依赖处检查flush/invalidate/内存屏障与缓冲生命周期。
- 同一帧的RGB、原始透射率、大气光、CNN残差和输出保持关联。流水并行需要显式frame/ticket，而非靠“当前指针”猜归属。
- 采集、处理、显示所有权分离；已被显示/DMA读取的缓冲不得被下一帧覆盖。
- 无法反压的摄像头需要明确接收与拒收路径；FIFO标记、EOF和数据跨域一致，复位释放在相应时钟域同步。
- 视频ROI与算法输出尺寸分别定义；旧帧重复刷新不计新处理帧。下溢、坏帧、错误drain/abort均有明确完成事件。
- 独立像素期望验证小图和全尺寸视频路径；真实面板观察、物理CDC/IO与软件寄存器各有各的证据范围。

## 6. 构建门禁

保留源码/资产基线，在新staging中生成匹配BIT/XSA，再基于该XSA构建应用和FSBL。先读原脚本是否回写 `delivery/`，不要直接在不可变归档里构建。

完整顶层资源、目标器件/时钟、timing/DRC/CDC要对应当前变更。OOC通过不是整板通过，正WNS/WHS不代表CDC已解决；尚未完成时标 `NOT_RUN` 或具体失败状态，不复用父版本标志。
