# CNN 轻量化与 FPGA 实测验证

核心任务是把**画质预算 → 轻量化候选 → 数值契约 → RTL/PS 实现 → 匹配镜像 → 真实输入输出性能**连成可追溯链条。不用参数量、MAC、局部核周期或屏幕刷新率代替端到端收益。

## 先分清两种“优化”和两种验收

| 工作类型 | 是否改变模型/数学定义 | 验收方式 |
| --- | --- | --- |
| 减通道、降 CNN 分辨率、剪枝、改量化、微调等算法轻量化 | 通常会改变输出；建立独立候选和基线关系 | 在预先确定的画质/任务指标预算内验收，不要求与旧模型逐位相同 |
| 同一冻结模型的 CPU 加速、RTL 调度/访存/并行度优化和 PS/PL 集成 | 保持该模型的运算与数值契约 | 对固定参考进行元素/字节/逐层等价检查，按明确契约处理浮点容差 |

两类修改同时发生时拆成可审计步骤，不能以“画质相近”替代 RTL 正确性，也不能要求变窄模型与原宽模型输出完全一致。

## 按用户任务选择入口

1. **CNN 轻量化优化**：读取 [轻量化与受控实验](references/cnn-lightweight-optimization.md)。确定冻结基线、数据/训练条件和质量预算，再做最小可验证的候选实验。
2. **算法等价与 RTL/PS 集成**：读取 [数值契约与集成](references/equivalence-and-rtl-ps.md)。先定义参考与边界，再由算子/层到完整图、完整尺寸和连续帧验证。
3. **上板与 QSPI 核验**：读取 [上板与 QSPI 证据](references/board-qspi-evidence.md)。区分实现完成、JTAG 运行、Flash 读回、QSPI 运行、完整冷启动和长稳。
4. **真实 FPS 与异常统计**：读取 [运行计数口径](references/runtime-metrics.md)。对齐计数含义、镜像和完整时间窗，拆开新帧、重复、拒收与错误。
5. **继续本用户已有去雾工程**：按需读取 [项目证据索引](references/project-evidence-map.md)。历史参数与结果只用于定位，不能作为新实验默认值或当前通过结论。

只执行本次要求涉及的阶段。只审计 FPS 时不顺带训练；只创建 skill 时不运行算法实验；缺少板卡授权时可以继续离线核验，不启动调试器。原来的交付型 skill 不是本 skill 的运行依赖。

## 贯穿全流程的工作方法

- 固定输入尺寸、数据划分、checkpoint/权重、预处理/后处理、数值格式与图结构身份；改变其中任一项就记录新版本，而不是覆盖通过标记。
- 轻量化先筛画质与实际图计算/内存负担，再核实映射收益。候选选择只比较同一负载、同一指标定义和同一验证层次的数据。
- 长训练/综合前做小规模 smoke；先确认预算、现有运行状态和输出目录。不要重复启动 RUNNING 作业或为了自己的任务终止他人的进程。
- 训练、校准、验证选模、最终测试职责分离。保留失败候选和所有预定种子，不选“最佳种子”冒充稳定收益。
- 数学定义、量化边界和输出裁剪不能在性能优化时被悄悄改变。对随机/极值/边界、复位、背压、重复帧及跨帧缓存依赖作针对性检查。
- 保留每阶段 `PASS / FAIL / NOT_RUN / RUNNING` 及通过范围。软件参考、逐层夹具、完整 RTL 图、OOC、整板实现、现场板测各是独立证据。
- 用全新 staging 做重建；先读原脚本实际写入位置，防止它覆盖 `delivery/`、报告或已验证镜像。新 BIT/XSA/ELF/FSBL/BOOT 不自动继承旧板测结论。
- 负载/时钟/器件/图像尺寸不一致时不直接比较 FPS；正时序不消除 CDC，零错误计数不等于零丢帧，工具估算功耗不是整板实测。

## 每个候选最少记录什么

保留已有项目结构，只补缺失的关键记录：

- 候选ID、父基线、改动因子、源码/权重/数据清单哈希，实际工具与命令。
- 参数量、按真实图统计的 MAC 定义、峰值激活/缓冲、DDR 读写及已实测的资源/周期；未测就标未知。
- 相对原始基线的累计画质差，以及相对上一阶段的增量差；协议、种子/分组统计与最差样本。
- 冻结参考的数值契约、测试覆盖、差异和首个不一致位置；完整图是否真正由上一层 RTL 输出驱动。
- 镜像/输入负载/运行时间窗、新帧吞吐、重复呈现、拒收、各错误计数及残留 CDC/冷启动/长稳问题。

只有当前阶段所需证据闭合才晋升候选；画质不通过可以是有效实验结果，不一定是程序执行失败。实际未执行的验证不得填 PASS。

## 离线复算工具

`scripts/audit_v5_runtime.py` 是自包含 Python 标准库脚本，仅适用于已有 V5 的 CSV 字段和计数定义。它复算新帧/处理/重复呈现速率、拒收比例、8类错误及可选硬件时间戳，对照归档 RESULT 和本地 BOOT 哈希；不连接板卡。

```powershell
python <skill目录>/scripts/audit_v5_runtime.py --samples <samples.csv> --reference-result <RESULT.json> --clock-hz <匹配设计计时频率Hz> --boot-image <BOOT.bin> --out <新的结果文件>
```

不确定计时频率时省略 `--clock-hz`，不复制历史50MHz作为默认值；字段或计数语义不同时先建立明确映射，不能直接套公式。`AUDIT_COMPLETE` 只代表离线复算成功，绝非新板测或验收通过。
